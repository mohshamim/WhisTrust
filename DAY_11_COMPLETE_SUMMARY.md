## 🔧 **Technical Implementation:**

### **Form Data State:**
```typescript
{
  category: string;
  title: string;
  description: string;
  priority: "low" | "medium" | "high" | "critical";
  source: "phone" | "in_person" | "email" | "walk_in" | "written";
  reporter_email: string;
  reporter_phone: string;
  internal_notes: string;
  has_contact_info: boolean;
}
```

### **Validation Logic:**
- Category: Required
- Title: Required, non-empty
- Description: Required, min 50 characters
- Source: Required
- Contact Info: If checkbox checked, need email OR phone

### **API Request:**
```typescript
POST /api/reports/create
{
  userId: string;
  category: string;
  title: string;
  description: string;
  priority: string;
  source: string;
  reporter_email: string | null;
  reporter_phone: string | null;
  internal_notes: string;
  is_anonymous: boolean;
}
```

### **Database Fields Set:**
- `organization_id` - From admin profile
- `category` - From form
- `title` - From form
- `description` - From form
- `priority` - From form (default: medium)
- `status` - Auto-set to "submitted"
- `source` - From form (phone, in_person, etc.)
- `reporter_email` - Conditional
- `reporter_phone` - Conditional
- `is_anonymous` - Based on contact info checkbox
- `submitted_by` - Admin user ID
- `internal_notes` - From form
- `case_number` - Auto-generated by database
- `tracking_code` - Auto-generated by database

## 🎯 **Use Cases:**

### **Scenario 1: Phone Call**
Employee calls hotline → Admin takes notes → Creates case with source="phone"

### **Scenario 2: In-Person Meeting**
Employee reports in person → Admin documents → Creates case with source="in_person" and optional contact info

### **Scenario 3: Email**
Report arrives via email → Admin transfers to system → Creates case with source="email"

### **Scenario 4: Walk-In**
Someone walks into office → Admin records details → Creates case with source="walk_in"

### **Scenario 5: Written**
Physical complaint form submitted → Admin digitizes → Creates case with source="written"
